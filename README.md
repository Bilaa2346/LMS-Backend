# LMS Kampus — Backend

Express + TypeScript API for the Campus LMS. Data is stored in JSON files
under `src/data/` (generated by the seed script).

## Quick start

```bash
cd backend
npm install
cp .env.example .env      # then edit JWT_SECRET
npm run seed              # generates src/data/*.json with demo accounts
npm run dev               # starts API on http://localhost:5000
```

## Security posture (M1)

- Passwords hashed with bcrypt (cost 10). Never returned by any endpoint.
- Auth via HTTP-only, SameSite=Lax JWT cookie (`lms_token`), 8h expiry.
- `helmet` headers, strict CORS (only the frontend origin), credentials allowed.
- `requireAuth` (401) and `requireRole` (403) middleware on protected routes.
- Input validation with zod at every boundary.
- Secrets loaded from `.env`, never committed.

## Endpoints

- `GET  /api/health` — public
- `POST /api/auth/login` — `{email,password}` → sets cookie, returns `{token, user, profile}`
- `POST /api/auth/logout` — clears cookie
- `GET  /api/auth/me` — requires auth → `{user, profile}`
- `PUT  /api/auth/password` — requires auth, `{oldPassword,newPassword}`
- `GET  /api/dashboard` — requires auth, role-specific stats
- `GET  /api/quizzes/mine` — requires auth, list of quizzes for current user (lecturer or student)
- `GET  /api/quizzes/courses` — requires auth, courses matching lecturer's study program
- `POST /api/quizzes` — lecturer/admin: create a new quiz with multiple-choice questions & answer key
- `GET  /api/quizzes/:id` — get quiz detail (student gets questions without answer keys)
- `PUT  /api/quizzes/:id` — lecturer/admin: update quiz details or toggle published status
- `DELETE /api/quizzes/:id` — lecturer/admin: delete quiz
- `POST /api/quizzes/:id/start` — student: start quiz attempt
- `POST /api/quizzes/:id/submit` — student: submit answers `{answers: [...]}` and receive auto-grading
- `GET  /api/quizzes/:id/attempts` — lecturer/admin: view student submissions, scores, and statistics
- `GET  /api/assignments/mine` — requires auth, list of assignments for current user
- `GET  /api/assignments/courses` — requires auth, courses matching lecturer's study program
- `POST /api/assignments` — lecturer/admin: create a new assignment (auto-notifies students)
- `GET  /api/assignments/:id` — get assignment detail
- `PUT  /api/assignments/:id` — lecturer/admin: update assignment
- `DELETE /api/assignments/:id` — lecturer/admin: delete assignment
- `POST /api/assignments/:id/submit` — student: submit assignment `{content, link}` (auto-notifies lecturer)
- `GET  /api/assignments/:id/submissions` — lecturer/admin: view submissions
- `PUT  /api/assignments/submissions/:id/grade` — lecturer/admin: grade submission `{score, feedback}` (auto-notifies student)
- `GET  /api/notifications` — requires auth, list of notifications & unread count
- `PUT  /api/notifications/:id/read` — mark single notification as read
- `PUT  /api/notifications/read-all` — mark all notifications as read
